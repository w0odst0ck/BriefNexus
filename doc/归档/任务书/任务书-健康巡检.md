## 需求（按方案实现，不改设计）

新增 CLI 子命令：`python -m intel check [--domain <域>] [--timeout N] [--interval S] [--output <path>]`

1. **定位采集器**：复用 `intel.core.registry.get_collector_classes / instantiate_collectors`（config 默认 `intel/config/sources.yaml`，--domain 过滤）
2. **巡检逻辑**（每个启用采集器）：
   - 实例化 → 建 session（UA 从 cli.py 现有 UA 列表轮换）→ 计时调用 `crawl(sess)`
   - **外层硬超时**：每源 --timeout 秒（默认 20s；crawl 内部 timeout=30 可能超，需外层兜底，可用 concurrent.futures 或 signal，选实现简单且不泄漏线程的）
   - 判定：正常返回 → `ok`（记录 items 数 + 耗时）；异常/超时 → `failed`（记录异常类名/消息摘要）
   - 串行执行 + --interval 秒间隔（默认 2s，礼貌抓取，不并发打源站）
3. **输出**：
   - 控制台表格：采集器 | display_name | 域 | 状态 | 条目 | 耗时 | 错误
   - 写记录：`intel/output/health-YYYY-MM-DD.json`（当日汇总）+ `intel/output/health-history.jsonl`（追加行：timestamp/source/status/items/duration/error，供时间线查询）
4. **退出码**：全部 ok → 0；任一 failed → 1；参数错误 → 2
5. **容错**：单源失败不中断其他源；crawl 抛任意异常都捕获为 failed
