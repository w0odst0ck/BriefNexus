## 扩展路径

### 第 1 步：汽车照明（Phase B）

汽车照明是与当前照明数据直接交叉的领域：

| ICS 代码 | 领域 | 与照明的关联 |
|----------|------|-------------|
| 29.140 | 照明设备 | ✅ 已有 |
| 43.040 | 道路车辆电气设备 | 车灯/信号灯 |
| 43.020 | 道路车辆综合 | 灯具通用要求 |

已经有好几条汽车照明标准在现有 355 条中（如 GB 4599-2024 汽车前照灯、GB 4785-2019 汽车信号灯），但它们被归入照明 ICS，缺少汽车维度的标注。

**任务**：
1. 用 SAMR 搜索汽车照明关键词（前照灯、信号灯、雾灯、led 车灯等）
2. 合并去重：新采的标准与现有照明标准做交叉
3. 打汽车标签（区分纯照明 vs 汽车照明）
4. 量级预估：300-500 条

### 第 2 步：汽车全行业（Phase C）

汽车照明满足后，扩展到汽车全行业：

| ICS 代码 | 领域 | 估计条数 |
|----------|------|----------|
| 43.020 | 道路车辆综合 | 200+ |
| 43.040 | 道路车辆电气设备 | 300+（含汽车照明） |
| 43.060 | 道路车辆内燃机 | 200+ |
| 43.080 | 商用车辆 | 100+ |
| 43.100 | 乘用车 | 100+ |
| 43.120 | 电动汽车 | 150+ |
| 43.160 | 专用汽车 | 100+ |

量级预估：**1500-2000 条**（不是全量国标 10 万+，可控）。

### 不做的事

- ❌ 全量国标采集（10 万+ 级别，成本高、维护重）
- ❌ 全 ICS 覆盖（只做照明和汽车相关）
- ❌ 企业标准/行业标准/地方标准（除非汽车照明领域有明确需求）

## 数据采集工具

### 当前状态

```bash
# 照明领域已验证的全量流程
python -m standards.crawler.main collect    # 关键词+ICS 扫描
python -m standards.crawler.main enrich     # ICS 代码补充
python -m standards.crawler.main fetch      # openstd PDF 下载（已失效）

# 搜索与检索
python -m standards.crawler.main search "LED"     # FTS5 全文搜索
python -m standards.crawler.main list --category 国标  # 过滤
python -m standards.crawler.main tree 29.140.40        # ICS 树浏览
python -m standards.crawler.main stats                # 统计
```

### 扩展汽车领域需要改动

1. `standards_config.ini` 增加汽车相关的 ICS 分类和关键词
2. `ics_tree.py` 补充汽车类 ICS 节点
3. 处理 ICS 多对多：一条标准可能同时属于照明和汽车（如 GB 4599）
4. 打行业标签（lighting / automotive_lighting / automotive_full）

## 知识图谱

### 实体与关系

```
GB/T 7000.1-2023  ──采标──→ IEC 60598-1:2020
  │                        │
  ├──引用──→ GB/T 7000.201    ├──替代──→ IEC 60598-1:2014
  ├──引用──→ GB 7000.203     │
  │                        └──ICS──→ 29.140 (照明)
  └──关键词──→ LED灯具
                │
GB 4599-2024  ──同源──→ 车灯类标准
(汽车照明)
```

### 可挖掘的关系

| 关系 | 来源 | 用途 |
|------|------|------|
| 采标 → IEC/ISO | intl_mapper | 双语对照、国际接轨 |
| ICS 分类 | SAMR 元数据 | 领域聚类（照明 vs 汽车） |
| 替代关系 | SAMR 元数据 | 标准版本追踪 |
| 归口单位 | SAMR 元数据 | 行业治理分析 |
| 跨 ICS 关联 | 多 ICS 标注 | 照明→汽车交叉 |
