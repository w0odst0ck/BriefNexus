# BriefNexus 产品书

> **版本**：v1.0 | **日期**：2026-08-28
> **一句话**：一个可挂载的 HTTP 信息采集公共服务——内置采集器与路由表，任何应用即连即用，数据永不出调用方项目。

---

## 一、产品定位

BriefNexus 是**信息采集的基建平台**：对内是采集内核，对外是 HTTP 服务。

**核心价值**：任何需要数据的应用，通过 HTTP 接口即可复用采集能力——**不共享代码、不耦合仓库、不绑定平台**。

**一句话**：你不需要知道采集器长什么样，调用接口就有数据。

```
┌─────────────────────────────────────┐
│          消费方（任意应用）           │
│  通过 HTTP 接口调用，零代码耦合        │
└──────┬──────────────────────────────┘
       │ HTTP (JSON)
┌──────▼──────────────────────────────┐
│     BriefNexus 采集平台（服务层）      │
│  HTTP API → 任务队列 → 采集内核        │
│  → 内存态存储（零磁盘数据文件）          │
└─────────────────────────────────────┘
```

---

## 二、三条核心目标（用户原话沉淀，2026-08-28）

### 目标 1：基建产品——提供可挂载的 HTTP 服务公共平台

- 内置**信息采集器 + 路由表**，任何人/任何应用都可以连接并使用
- 通过 HTTP 接口：提交任务 / 查状态 / 拉结果 / 收回调
- 扩展采集器可**平台外挂载**（extra_dirs），平台仓零改动——加源不改内核
- 消费方不知道也不关心采集器内部，API 稳定不变

### 目标 2：完全解耦 + 数据隐私（核心思想）

- **完全解耦**：平台只留存采集器 + 平台自身数据，不包含任何业务项目的代码或数据
- **数据隐私**：采集数据对客户完全保密——数据不出调用方自己的项目
- **分流铁律**：涉业务机密的数据源必须客户端挂载（业务项目内），平台不碰
- 平台内存态存储（零持久化），进程重启即清——不留下任何业务痕迹

### 目标 3：轻量，内核小

- 纯 Python（FastAPI），核心 ~12k 行，无重依赖
- 内存态任务/结果/去重，无数据库引擎、无文件句柄、无临时文件
- 单服务即可运行，部署成本趋近于零

## 三、核心能力

### 3.1 HTTP API（即连即用）

| 端点 | 功能 |
|---|---|
| `POST /v1/collect` | 提交采集任务（异步） |
| `POST /v1/collect/sync` | 同步采集（等结果） |
| `GET /v1/tasks/{id}` | 查询任务状态 |
| `GET /v1/tasks/{id}/items` | 拉取采集结果（支持消费即清） |

统一 JSON 协议，任何语言/框架都可调用。

### 3.2 内置采集器 + 路由表

- **内置通用采集器**（多项目可复用的公共情报源）：
  - 官方源：白宫 / 欧盟委员会 / 美联储 / SEC EDGAR / NVIDIA 博客 / GlobeNewswire
  - 学术源：arXiv（自动驾驶感知方向）
  - 行业源：ADAS 国际季刊
  - 合规源：SFDA / SASO / GSO / 国标 / ASTM
  - 高难源：东财要闻 / 巨潮资讯（CDP 渲染绕 WAF）/ BOSS 直聘（浏览器渲染）
- **路由表**（config.d）：按项目/用途组织挂载目录，机制通用、内容分离

### 3.3 采集器外挂机制

```
平台内置（intel/collectors/）    客户端挂载（业务项目 extra_dirs）
  通用 / 公开 / 平台维护       →  业务特定 / 机密 / 业务自维护
```

判断公式：`通用 ? 多项目用 ? → 内置；涉业务机密 ? → 客户端（铁律）`

### 3.4 内存态 + TTL + 交付即清

- 零持久化：全部状态在进程内存，重启即清
- TTL 过期自动回收（惰性 + 主动双回收）
- 交付即清：结果被消费后立即释放，不留痕

## 四、客户成效

| 场景 | 传统方式 | 用 BriefNexus |
|---|---|---|
| 应用需要外部数据 | 自己写爬虫/对接每个源，重复造轮子 | 调一个 HTTP 接口，复用现成采集器 |
| 业务敏感数据采集 | 采集逻辑放平台，数据过第三方 | 采集器挂载自己项目，数据不出门 |
| 加新数据源 | 改平台代码，牵一发动全身 | 平台外挂载新采集器，内核零改动 |
| 多项目共用采集 | 每个项目各写一套 | 一套平台，多项目即连即用 |

## 五、快速上手（三步）

1. **起服务**：`python -m platform.run`（FastAPI :9000）
2. **提交任务**：`POST /v1/collect`（指定采集器 + 参数）
3. **拉结果**：`GET /v1/tasks/{id}/items` → 拿到结构化数据

扩展新采集器：按模板写一个 collector → 挂到 extra_dirs → 路由表登记，平台仓零改动。

## 六、数据与隐私承诺

- **零持久化**：平台不落盘业务数据，进程重启即清
- **零耦合**：平台仓不含任何业务代码/数据
- **机密分流**：涉密数据源客户端挂载，平台物理不接触
- **消费即清**：结果交付后立即释放
